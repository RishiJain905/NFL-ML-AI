## 1. The no-touch rule first (D107)

- New code lives in `src/nflengine/playcalling/`; it **never imports** from `nflengine.models` or `nflengine.features` and never writes to production folders, aliases or the weekly run. It may import small infrastructure (`paths`, `fsutil`, `ops.lock.write_parquet_atomic`, `ingest.base.SnapshotStore`, `tracking`) and read curated data.
- Shared files change only by adding: the `nfl playcalling` CLI group, the `playcalling:` settings block (PC02: its `forecast:` sub-block), `AppConfig.playcalling`, `DataPaths.playcalling`.
- **PC02 reads LD00's models** (`nflengine.live`: `data`, `models`, `schema`, `train.load_production`): a feature-track module, allowed; for a finished season it refits LD00's `wp` + `pass` itself (never `nfl live train`, never the LD00 bundle on disk).
- Every PC phase closes with the production-unchanged check (`tests/test_production_untouched.py` + a week-5 rehearsal into the scratchpad on C:; the `live-decisions` skill §7 has the recipe; PC00: games 30 / players 4,542 / teams 120 identical, max diff 0).
- **The refresh is not a weekly-run step** (D122, D132): never add it to `weekly.py`. Since D132 one control-room button, **Update play calling** (the current week's Play calls tab), runs `nfl playcalling update --auto` (`update.py`), which does only what's due: Monday night's FTN (≥ 30 h after kickoff), the build, last week's decision review, last week's grade, this week's forecast.

## 4. Rules that bite

- **Polars scalar trap:** `pl.lit(True) & pl.lit(True)` is one scalar, and its `.sum()` inside a `group_by` is 1, not the group's row count (`dropback_rate` × `all` came out as n = games). `team_game_sums` ANDs every condition with a per-row `True`; keep it when adding a metric whose `den` is a literal.
- **Plays files differ in dtypes by season** (`goal_to_go` f64 vs i32): `load_inputs` reads each `plays/season=YYYY.parquet` separately and casts numerics to f64 (`INT_COLS` excepted) before a diagonal-relaxed concat. A multi-file `scan_parquet` raises a SchemaError.
- **FTN placeholder rows:** FTN keeps rows for plays it didn't chart (`qb_location` '0', box 0, every flag False; 2024_07_BAL_TB 97 of 131 plays; 2023 65, 2024 260, 2025 47, 2026 5 scrimmage plays). They're dropped, so the play is `ftn_charted` False; otherwise they count as "no play-action / no blitz". One 2024 row has `qb_location` ' S' (strip first).
- **FTN timing:** nflverse pulls FTN at least twice a day (~11:00 and ~17:00 UTC); FTN lands ~35-51 h after a game. Tuesday evening has every game but Monday night's; Wednesday afternoon completes the week. `build.json → coverage.games_without_ftn` lists what's missing. FTN metrics count charted plays only, so a missing game shrinks `n`, never biases a rate. FTN re-stamps the whole season every pull.
- **Availability (D123, Sol):** an as-of-W row is what a run on the Tuesday night before week W could see. `as_of_cutoffs` = end of the Tuesday (US Eastern) after the last game before W, capped at week W's first kickoff; `held_back` takes out FTN rows of a game until kickoff + `FTN_LAG_HOURS` (48) and the PFR metric for `PFR_LAG_WEEKS` (1); `tendencies(held=)` subtracts them from `season` and `last4` (`games` unchanged). Monday night's FTN counts from the next week, so Tuesday and Wednesday builds give the same as-of tables; `build.json → availability` names the held games. `games` needs `kickoff_utc`: without it (or with a null kickoff) the rule **fails closed** and holds the previous week's FTN for a week. Brute-force check (opus-high, after the fix): 5,376 windows, 0 mismatches; capped cutoffs only in 2020 W6 / W13 / W14 and 2021 W16 (Tuesday / Wednesday games).
- **Required columns:** `load_inputs` refuses a plays file missing any of `REQUIRED_COLUMNS` (a missing `pass` once read every play as a run); other missing columns become null with a note.
- **As of a week:** `as_of_week` W sums games with `week < W` (season, last4) or every game of S−1 (`last_season`). As-of weeks stop at the first week not complete in `games` **and** in the curated plays. Brute-force check (opus-high, PC00): 1,080 windows recomputed from plays, 0 mismatches.
- **`last_season` keeps only metrics that exist in season S** (`Metric.exists_in`): no 2025 participation on 2026 rows, no NGS-era formation on 2023 rows.
- **Participation is research only** (`history_only` rows). Never a feature for a forecast (PC02 must filter `~history_only`); pages label it "History". Two vocabularies (NGS ≤ 2022, FTN ≥ 2023); `formation_shotgun` changes meaning (NGS splits EMPTY out). Coverage 0% in 2016-17. FTN-era `was_pressure` is False on runs too (filter to dropbacks).
- **PROE isn't 0 for the league:** `xpass` (nflverse, fit 2006-2019) isn't re-centred; league neutral PROE −0.2 to −1.9 points in 2016-2021, −1.2 to −2.6 since (2025 −2.0, rbsdm −1.7). Compare teams with `diff`. Our neutral rule (downs 1-3, not the last 2 min) is narrower than rbsdm's PROE tab (all downs, all clock, penalty plays in): Spearman 0.975 on 2025's 32 teams, same top 5, 4 of the bottom 5.
- **Definitions from the data:** dropback = nflverse `pass == 1` (`pass_oe` = 100 × (pass − xpass) exactly); pbp `shotgun` includes pistol; the gamebook's `pass_length` "deep" starts ~16 air yards (the pass zones use it; deep shots use air ≥ 20); `run_gap` is null on middle runs; PFR blitz = `pfr_pass.times_blitzed` per opponent dropback (team = offense, opponent = defense), r 0.72 per team-game / 0.86 per team-season vs FTN.
- **Defense rows** are what offenses do against the team; their situations are from the offense's side (a defense row's `lead_9plus` means the opponent led). Playoff games count in every window.
- **Percentiles** rank every team with `n > 0`, however small: read `n`.
- **Sizes:** 2025 `team_tendencies` ~944k rows (~95 MB in memory); a history build keeps only slimmed builds for W&B. The data drive is slow for small writes; the four files per season are fine.

## 4a. The pages (PC01)

- **Where:** the control room's Explore → Play calling (`/explore/play-calling`, a team at `/explore/play-calling/KC`) and the `play-calls` week tab after Game day. The backend is `src/nflengine/app/readers/playcalling.py` (the `control-room` skill §4e has the endpoint and web rules); the web pages are `web/src/pages/explore/` and `web/src/pages/week/PlayCallsTab.tsx`.
- **What the pages read, and as of when:** a team page and the grid read a season's **newest** as-of week (`build.json -> as_of_weeks[1]`), `window` season (last_season when the as-of week is 1); the week tab reads **as of its own week** (`not_yet` past the newest). Only `team_tendencies` (+ `team_game_tendencies` for the sparklines, curated `games` for the slate); never `plays_enriched` (PC03) or `league_tendencies` (`league_value` is on every row).
- **Rules the reader enforces** (keep them when adding a number): `small` = n < 20; `~history_only` everywhere but History; History = the newest three built seasons from 2023 with `history_metrics: true` (one vocabulary); PROE and dropback rate read in `neutral`, everything else `all`; the defense's own calls are `_DEFENSE_CALLS` (blitz, PFR blitz, rushers, box, man, pressure), everything else on a defense row is "what offenses did against it" and carries the "depends on the offenses faced" note; the grid's defense signature falls back to `blitz_rate_pfr` for 2018-2021 (no FTN) and to the defense's `proe` for 2016-2017 (no blitz data); `situations.metrics` and the week tab's `metrics` keep only metrics with data that season; `next_game` skips games already kicked off (`get_team(now=)`); the weekly series stops before the as-of week; a week tab's `ftn_waiting` lists only earlier weeks' games; `history_seasons` needs `history_metrics is True`; a games table without its key columns is "no games" (all from the PC01 cross-review).
- **The descriptive matchup "shift"** (PC01, not a forecast): the defense's `diff` / the sample SD of the defenses' values in that window and situation (non-small defenses only, also for the rank phrase); the shifts list needs |shift| >= 1, neither cell small, one per matchup, up to 8. PC02 replaces the description with a forecast; keep the field names (`offense`, `defense`, `league`, `shift`) so the tab can add `forecast` beside them.
- **Wording from the spot checks** (guide §8.6): play-action is **per dropback** (public sites quote per snap: KC 2025 15.3% = 10.0%); our blitz is FTN's 1+ blitzer (Sharp's is 5+ rushers: MIN 2025 51.2% vs 46.0%); our deep shots are 20+ nflverse air yards (public ranks differ); never set our man / box rates beside Sharp's (different charters); with rbsdm's own filter our PROE equals rbsdm's exactly for all 32 teams.
- **Checks:** a brute-force script compared every cell the reader returns (86,168 for 2026, 2025, 2019) with its parquet row: 0 mismatches. Repeat it after changing the reader (the session's scratch `verify_reader.py` pattern: `get_team` / `get_teams` / `get_play_calls` / `get_history` vs a dict of the rows keyed by team, side, metric, situation, window).

## 4b. The forecast (PC02)

- **One as-of rule:** the design rebuilds the as-of sums from `team_game_tendencies` with PC00's availability (FTN = kickoff + `FTN_LAG_HOURS` <= `as_of_cutoffs`; a null kickoff holds FTN a week). Its raw sums (`a["K0"]`, `a["N0"]`) equal `team_tendencies`' `season` window on the real data (integration test): keep it so when changing either.
- **Rate scale, one formula:** forecast = team term + lam × context effect + script, clipped. `kappa` is in plays; `rho_new` applies when `coach_changes` flags the side (head coach at the first game vs last season's last, or the seed's OC / DC names); games before a mid-season head-coach change weigh `pre_change_weight` in the team term only (never in the league or a venue).
- **Context = opponent or venue** (`Target.context`): run direction uses the venue (the game's home team): the home stats crew charts `run_location` (D130). A row whose game isn't in `games` falls back to the opponent.
- **The script** (PROE, dropback rate): x1 = the season's `ScriptCurve` at the team's spread minus its mean, x2 = (total − the curve's mean total) / 10; observations are script-adjusted inside `predict_parts` (`K - b_spread·X1 - b_total·X2`), so the same betas adjust and add back. Each season's games use **that season's** curve (curves for S−1 too: the prior).
- **Every predictor has its own fit** (`fit_kind`, per-play squared error); b1 / b2 have none. A target without a script: `model` ≡ `b4`. Score on **one cohort**: rows where every kind and the actual are finite (FTN 2022 week 1 has no league rate: dropped).
- **The ship rule** (`ship_verdict`, D130): MAE < b2 in ≥ 5 of 7 (FTN 3 of 4) seasons, ties at 4 decimals don't count, pooled MAE ≤ b3's. Write any new rule down before the reported run (a timestamped scratch file, then the decisions log).
- **Ranges:** NNLS on squared errors for (c, b), then the 10th / 90th percentile of the tuning errors in SD units with the plays a forecast **expects** (`expected_plays`), so the reported coverage is what the pages show.
- **Overall MAEs mix units:** `rushers_avg` is in rushers; the reader's `graded.overall` / `forecast_record.overall` and the CLI / W&B week summary average only the targets in points (shares, PROE); per-target MAEs include rushers (the UI worker caught both the mix and a regression that dropped rushers per target).
- **Backfills:** a forecast made after a game's kickoff marks it `after_kickoff` (`forecast.json → games_after_kickoff`, the pages' badge). 2026 weeks 1-5 are a backfill (2026-10-11); a backfill's lines can be closing lines, and the pages say so.
- **Leaks Sol found (D131), keep them closed:** `expected_plays` (the range's plays) never reads the design's own actual `n` (league per team-game as of the week, then last season's, then 30); `run_forecast` refuses a season in any target's `fit_seasons` (in-sample parameters); `load_model` accepts only a `VERSION_RE` stamp resolving inside `models/playcall`; the reader attaches a scoreboard row only when its `version` and `made_at` match the forecast row (`_same_forecast`).
- **Pages:** only `shipped` rows reach the answers; team codes through `_canon`, game ids through `clean`; the production version string matches `_VERSION_RE` before it names a folder; the server writes every sentence (shift reasons: opponent / venue crew / script / shrinkage, "last season" in week 1, "few" only for ≤ 2 games).

## 4c. The play diagrams and the play browser (PC03)

- **Never present a reconstruction as real** (the phase's first pitfall): `LABEL` is in every answer and the player draws it in every state. A spot the data doesn't give is `approx: True` and listed under `approximate`; the count may be known (the box: FTN; receivers: 11 − OL − QB − backfield) while the spots aren't. `unknown` always lists other receivers' routes, coverage assignments and blocking. The pre-snap phase text names only what's known (no default "7 in the box").
- **What each era gives** (the guide §10 has the table): 2026 = play-by-play + FTN (hash, QB alignment, backfield, box, rushers, motion, play-action / screen / RPO; no personnel or coverage until ~February 2027); 2023-2025 + participation (personnel, coverage shell, the target's route, time to throw); 2022 the same in NGS vocabulary; 2016-2021 participation without FTN (no hash, no motion; QB alignment from pbp `shotgun`, box / rushers from participation).
- **Rules that bit (the test worker and the brute-force run over all 2016-2026 plays):** nflverse `touchdown` is 1 for a defensive score (pick-six, fumble return): use `offense_touchdown`; a fumble the defense recovered is only in `desc` ("RECOVERED by XXX-", also lowercase "recovered by" on aborted snaps) and its team code may be old (OAK vs the row's LV): compare through `curate.teams.TEAM_MAP`; a fumbled snap the QB picked up and threw is that pass (`aborted` is True on it); one 2016 row is both a scramble and a completed pass (a pass attempt wins); sub-minute clocks are written `(:05)`; safeties at LOS + 12 near the goal line left the field (every x is clamped to [−9.5, 109.5]); fake kicks ("(Punt formation)") and direct snaps are tags from `desc`.
- **The play list** (`app/readers/playbrowser.py`, `get_team_plays`): one filtered read of `plays_enriched` (team + week, `memory_map=False`); weeks from the team's games (a bye = `no_week`); filters `down`, `type` (`TYPES`), `result` (`RESULTS`) on the server; `desc` through `clean()`, team codes through `_canon`. The diagram reads the whole game (for the QB ids) and the play by `play_id`; an unbuilt season, an unknown game or play is a fixed-text 404.
- **The generic spots are measured medians (D133 (5)):** `QB_DEPTH`, `DROP_DEPTH`, `WIDE_Y` / `SLOT_Y` / `SLOT2_Y`, `DL_X` / `LB_X` / `CB_X` / `OVERHANG_X` / `SAFETY_X` and the back spots came from real 2023 tracking (BDB 2026, 14,107 plays joined to nflverse + FTN; the guide §10.4). Change one only with a new measurement and update §10.4. Only the center over a charted ball and the QB at a charted alignment are `approx: False`; everyone else is generic (Sol, D135).
- **Rules from the reviews (D135):** every string of a diagram answer, a play-list row and a real clip goes through `clean()` (`playbrowser._clean_strings`): the known / approximate lines quote file values; a run or scramble that lost yards stops behind the line (`min(los + 0.5, end_x)`); a fumbled snap from punt formation isn't a fake; real clips drop frames without finite x / y and a play that can't be drawn is skipped (never the build); the library swap uses `fsutil.replace_file` and restores the old library; Kaggle credentials with whitespace are refused before any request and every httpx error becomes a fixed-text `KaggleError` (a protocol error can quote the Authorization header).
- **Big Data Bowl terms (D134):** CC BY-NC 4.0, non-commercial, no redistribution: the raw files and the library stay on D:; nothing from them in git (the repo is public), W&B, a published mockup or a test fixture (tests use synthetic frames). Download only with Rishi's OK in chat, after stating the files and sizes (`--list`). BDB coordinates: x 0-120 with the end zones, y up the page; to the diagram's frame a right-moving play is (x − 10, 53.33 − y), a left-moving one (110 − x, y). Check a Kaggle edition's file list before planning on it (`nfl playcalling library --list`, or the probe in PC03's session log): editions get withdrawn (BDB 2025 / 2024 serve only a README since before 2026-10-17).
