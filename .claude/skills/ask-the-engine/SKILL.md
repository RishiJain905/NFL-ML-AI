# Ask the Engine (the query layer)

Spec: `documentation/ask-the-engine/README.md` (+ phase files AE00-AE04). Plain-language guide: `documentation/guides/ask-the-engine.md`. Decisions: D107, D108, D111, D112, D136-D139.

## 1. The rules first

- **No-touch (D107):** Ask only *reads* the weekly graph and the curated tables. Never add an index, a node or a property to the weekly graph for Ask (names resolve in Python); never change the digest's `llm:` block, a production model, the weekly run or the graph's loaders. New code lives in `src/nflengine/ask/`; `digest/` helpers may be imported read-only (`digest.format.number_atoms`, `digest.llm.openrouter._json` / `_error_text`, `digest.names.TEAMS`). `tests/test_production_untouched.py` must pass.
- **Every query goes through the guard** (`guard.Sources.run` / `run_cypher` / `run_sql`), templates included. Nothing else in `ask/` opens a Neo4j session or a DuckDB connection.
- **Never write a database's error text to files, logs or W&B.** `QueryFailed.hint` (scrubbed, capped) goes only into a correction prompt; results keep `kind` + `code`.
- **Never loosen a guard rule without a red-team test** for what it now lets through, and the live probes (`uv run pytest -m integration tests/ask`) still passing.

## 3. The guard: how each part works (and why)

**Cypher** (`check_cypher` on `_scan`'s skeleton: strings emptied, comments dropped, line comments end at `\n` **or `\r`** like Neo4j's lexer):
- one statement; no backticks; **no `\u` / `\U` escape anywhere in the raw text, strings and comments included** (`_UNICODE_ESCAPE`: Neo4j 5.26's `UnicodeEscapeReplacementReader` decodes them before lexing, so `'' + apoc.version() + ''` closes the string and an escaped newline ends a `//` comment; Sol, AE00), and no other backslash outside strings (`apoc` is `apoc`); no `:` commands;
- a word is a clause only where Cypher reads one: `n.set` (property), `:Set` (label), `{set: 1}` (map key), `$create` (parameter) are fine; the word after `..` (a slice) is **not** a property access;
- write words (`CYPHER_WRITE`), banned words (`CYPHER_BANNED`: LOAD, USE, SHOW, EXPLAIN, PROFILE, CYPHER, TRANSACTIONS), `CALL` not followed by `(` / `{` (a procedure), the namespaces apoc / gds / dbms / db / genai;
- **any namespaced function call** (`_FUNCTION`: `x.y(`) must start with a Neo4j namespace (`CYPHER_FUNCTION_NAMESPACES`: date, datetime, localdatetime, localtime, time, duration, point, vector). Plugin functions don't show in the plan: `apoc.cypher.runFirstColumnSingle('…')` runs a nested query (the AE00 test worker got one through `apoc` and `[0..apoc.x()]` before these rules);
- then `EXPLAIN` in a READ session (`query_type == 'r'`, no `ProcedureCall` / `LoadCSV` operator), then `execute_read` with `unit_of_work(timeout=)` (Neo4j stops ~1 s past it), `cap + 1` rows read. Values: scalars and lists; nodes / relationships / paths / maps refused (`cypher.values`); `allow_maps=True` only for `library:` templates (Q3, Q4, Q5's tree build maps).
- Length: 8,000 characters **without comments** (the library's files are heavily commented; q2 is 9.7k raw), 32,000 raw.
- Live probes (2026-10-17, Neo4j 5.26 Community): `dbms.listConfig` and `SHOW USERS` **run** in READ mode; `LOAD CSV`, `apoc.load.*`, `apoc.export.*`, `gds.graph.project`, `apoc.util.sleep` plan as `r` (LOAD CSV tried the file): the text check is the real stop. Writes in a READ transaction: `Neo.ClientError.Statement.AccessMode`.

**SQL** (`SqlSandbox` + `check_sql_plan` + `run_sql`):
- The connection has **no file access** (`enable_external_access=false` at connect, no allowed directories, autoload / autoinstall off, `python_enable_replacements=false`, no temp directory, then `lock_configuration`). **Never use `allowed_directories`**: DuckDB then also *writes* there (a `COPY ... TO` landed in curated, `ATTACH` opened `nfl.duckdb` read-write; probe 2026-10-17).
- `check_sql_plan` first runs two **lexical** checks with `duckdb.tokenize` (it reads no file): the first word is in `SQL_FIRST_WORDS` (select, with, from, values, table, pivot, unpivot, "("), and a `;` token may only be followed by more `;` (comments aren't tokens). Both exist because DuckDB's parser itself reads `<dir>/schema.sql` for `IMPORT DATABASE '<dir>'`, even as a second statement (test worker; Sol). Parsing then uses `con.extract_statements` on the locked connection (file access off) → one `SELECT`; `json_serialize_sql` (DuckDB's own parser, run in the locked connection) → every `BASE_TABLE` must be a curated table or a CTE (schema '' / main, catalog '' / memory), `TABLE_FUNCTION` only range / generate_series / unnest, no banned `FUNCTION` (`BANNED_FUNCTIONS`, `BANNED_FUNCTION_PREFIXES`: duckdb_*, pragma_*, read_*, glob, query, current_setting, getvariable ...). It also returns the tables, every `COLUMN_REF` name and JOIN `using_columns`, and the tables a `*` expands over (`_star_tables`: only the tables the starred SELECT reads directly; a star over a CTE or subquery doesn't count; NATURAL JOIN counts).
- `run_sql` then **reads only those columns of those tables into memory, file by file** (`SqlSandbox.load`: `pq.read_table(memory_map=False)`, cast to the unified schema: `plays`' `goal_to_go` is int32 in some seasons, f64 in others), registers them, and runs `SELECT * FROM (<q>\n) AS ask_capped LIMIT cap + 1` with a `con.interrupt()` timer. `*` over a table wider than `WIDE_TABLE` (60) → `sql.star`; more than `MAX_COLUMNS` (100) of one table → `sql.columns`. Every column is needed (a "star table") for: a bare `*`; `t.*` (only `t`'s table: `_star_tables` scopes by `relation_name`); a whole-row reference (`to_json(t)`, `t::VARCHAR`: a one-part COLUMN_REF naming a table or alias); a positional `#1`; PIVOT / UNPIVOT (both serialize as `PIVOT`); NATURAL JOIN; a column-alias list (`teams AS t(a, b)`: `column_name_alias` renames by position). A CTE may not shadow a curated table's name (`sql.table`). One deadline (`t0 + timeout_s`) covers the checks, `load(..., deadline=)` (checked between files) and the run (the interrupt timer gets the rest); Cypher likewise: `EXPLAIN` runs as `Query(..., timeout=)`, the run gets the remaining budget.
- **Why in memory (D136):** on Windows a reader that holds a Parquet file for the whole query (a native `read_parquet` view, *and* an Arrow dataset) makes the curate step's `fsutil.replace_file` fail after its 2 s retry. File-by-file reads hold each handle ~0.1 s. All-season `plays` with 3 columns: 0.11 s.
- **The weekly lock:** `Sources.busy()` = `ops.lock.is_locked(runs/.weekly.lock)` (the control room's check). While a weekly run, an injury update or Update play calling holds it, `Sources.run` raises `source.busy` and `ask()` refuses at the start: the tables are being replaced and the graph may be mid-rebuild.

## 4. Templates (`config/ask_templates.yaml`)

- Schema in `templates.py`'s docstring; `load_templates()` validates (ids, `$refs`, `{slots}` need a fragment choice, filters, examples). Graph template text is **comment-stripped at load** (`strip_cypher_comments`), so `{x}` / `$x` in comments never count; `library:` templates never substitute slots and can't use fragment choices.
- Values are bound (`$name`; DuckDB and Neo4j both take it); only `choice` fragments from the YAML enter the text. `asof: true` binds `$season` / `$week` to the weekly graph's week (`route.graph_asof`: the newest live `runs/<S>/week<NN>/graph_results.json` with status ok); the LLM's values for them are ignored.
- AE00 built 49 (34 graph: the 16 library queries + 18 relationship templates; 15 SQL). Every example rendered and ran (101 cases, warm ≤ 0.24 s). Quiet this week is legitimate (q5 / q8 / q9 often 0 rows).
- Adding one: write it, `load_templates()`, run its examples through `Sources.run` (`allow_maps=True` only for library ones), add a golden question, `uv run pytest tests/ask`.

## 5. Names (`names.py`)

- Teams: codes count only in capitals in a question ("NO"), any case as a parameter value; nicknames, cities (not New York / Los Angeles alone: ambiguous), old names (`EXTRA_TEAM_NAMES`), "Bills-Chiefs". Players: exact full names **first**, in any case ("mike williams" must still clarify; a lower-case window with a stop word is skipped) and before teams ("Dallas Goedert"), then teams, then near misses (`rapidfuzz` ratio ≥ 88 on capitalised 2-3 word windows), then a lone capitalised last name of a prominent player (16+ games). Coaches: schedules + `head_coach_fixes.csv` + the coaching seed.
- Ambiguity (`_decide`): same-name players with 8+ games; exactly one who played last season or this one wins; else `ambiguous` (choices ranked most recent first). A prominent player and a coach with the same full name: ambiguous; a coach and a never-played namesake: the coach ("Andy Reid"), also for a near miss ("Andy Ried").
- Real ambiguous names in the golden set: Mike Williams, Michael Thomas, Michael Carter, David Long. `players` has two "Justin Jefferson" rows (the WR and a 2026 LB) and the graph two "Josh Allen" nodes: references filter on position.

## 6. The router, corrections and answers (`route.py`, `answer.py`)

- Order: length and write-intent (`_WRITE_INTENT`) in code; the weekly lock; names (ambiguous → clarify, no LLM call); the router call (template / generate / refuse); a template's bad values or failure → back to the router; a generated query's refusal / error (with the scrubbed hint) / empty result → back to the generator, which may reply `{"accept": true}` for a true empty; at most `limits.corrections` (2) rounds. A template's empty result is final (no extra call).
- The answer: up to 40 rows to the LLM; `check_answer` against `allowed_atoms` (cells and their 0-4 decimal roundings, 0-1 shares as %, question numbers, template values, the row count, ordinals up to it) and, for numbers written with an explicit sign, `signed_atoms` (+0.24 against a row's -0.24 fails; a dash between numbers is a range, not a sign; Sol); a failure → `fallback_sentence`, no second call. `OutOfCredits` is re-raised from the answer step (an eval run must stop).
- `nfl ask --json` scrubs each string (`cli._scrub_tree`), never the serialised JSON (scrubbing the text turned `"prompt_tokens": 123` into invalid JSON).
- Latency: reasoning tokens dominate (Haiku 5.5 at "low": 1,144 completion tokens on one generation, 5.8 s); see the bake-off (D138) for each model's p50 / p95.
- **The conventions (D140) live in `schema.py` (`SQL_RULES`, `GRAPH_SCHEMA`, `TABLE_NOTES`) and the prompts, and the golden references follow them:** playoffs count unless the question says regular season (`games.game_type` 'REG' / 'WC' 'DIV' 'CON' 'SB', no 'POST'; `season_type` 'REG' / 'POST' elsewhere; `THREW_TO` / `PLAYED_FOR` include playoffs); one row for a single answer (the router sets `limit` 1), one row per entity for "which ...", league-wide unless a team is named; full names (plays' `*_player_name` are abbreviated); a game = `game_id` + both teams; per-play counts drop no_play and two-point tries; NGS season figures = the week-0 rows; teammates = overlapping `roster_weeks`; officials grouped by name. **Most of the 2026-10-18 audit's gains came from writing these down** (Luna "low" 71.4% → ~92% over three runs, held-out ~90% over two; one run varies ±3 points, so compare configurations over repeat runs, not one): before changing a model, read the misses against their reference rows (`scratchpad`-style dumps of the eval file's `tables`).
- `prompt_hash` covers the three prompt files **and** the schema text: a schema note change makes earlier runs incomparable in `nfl ask pick`, as a prompt change does.

## 7. The golden set and the bake-off (`evaluate.py`)

- `config/ask_golden.yaml` (99 questions: template 34, sql 26, graph 24, trick 15 = 4 clarify + 11 refuse; ids g001-g115). References run **on the day's data** at every eval (`reference_params` binds `$asof_season`, `$asof_week`, `$current_season`). A reference returns **the columns that are the answer**: the entities a "which / who" asks for, the numbers a "how many / what" asks for, labelled in the question's words, following the conventions (§6); not supporting columns (10 references were corrected for this in the audit, each noting why).
- `config/ask_holdout.yaml` (D140): 40 questions (ids g201-g240) written after the audit and **never used to tune anything**; `nfl ask eval --set holdout` (`run_eval(golden_set="holdout")`, file suffix `_holdout`, W&B tag `set:holdout`); `latest_summaries` skips it, so `nfl ask pick` never mixes it in. Don't fix the system from a held-out miss; if you must, say so and write new held-out questions. New questions go into the held-out file only after it has been run.
- `compare` (`SCORER_VERSION` 4; 4 = a one-item list equals its item, `['LAC']` vs `'LAC'`, unwrapped in `_unwrap` before a column is typed so `[0.28]` keeps the numeric rules): order-insensitive; extra system columns allowed; each reference column must match a distinct system column (`_column_transforms`), then the rows must match as a multiset; row counts equal. Numbers: `_equal(got, ref_value)` = the same, or the true reference rounded to the system column's precision (within half a unit, and the unit ≤ |ref|: 0.2843 vs 0.28 yes; 14 vs 15, 0.28 vs 0.29, 0.4 vs 0 no; scorer 1 had a whole-unit tolerance, found by the test worker); ×100 only for references in [0, 1]; text case-folded; lists as sets. A system column named like one reference column can't stand for a different one (swapped wins / losses fail; Sol), but a same-named column may mean something else (g022: the template's `coach` is the subject, the answer is `other`), so matching is otherwise by value. Write references with the minimal columns and **no ties at a LIMIT boundary**.
- Every eval file stores both result tables (`tables`, 200 rows each): `rescore(path, write=True)` / `rescore_all` / `nfl ask pick --rescore` re-score saved runs offline after a scorer change (bump `SCORER_VERSION`). `latest_summaries` reads only the current scorer version, complete runs (`golden_total`, not `partial`) and, from `nfl ask pick`, runs made with today's prompt / golden / template hashes (`current_hashes`).
- `run_eval` writes `{NFL_DATA_ROOT}/ask/evals/<stamp>_<model>_<effort>[_smoke].json` and a W&B run (group `ask-the-engine` / `ask-the-engine-smoke`, job `ask-eval`, name `ask-eval-<model>-<effort>`); it stops on `OutOfCredits` (exit 3: Rishi refills, then re-run).
- `pick` (Rishi's rule, D138, replacing D137's bounds rule): the best `exec_accuracy` whatever it costs or however slow; accuracies within `TIE_POINTS` (2 points: one question of 84) of the best tie, and a tie goes to the lowest `cost_per_question` (an unknown cost sorts last), then the lowest p95. `meets_bounds` (D137's 8 s / $0.002) is still computed and shown, never used. Costs (Sol's second review): a question with no LLM call costs $0; one whose calls lack a cost is unknown (`Scored.cost` None), and then the run's `cost_per_question` is None (`cost_unknown_questions` counts them): never in bounds, shown as "-" / "cost unknown", sorted last by `pick` (an unpriced local model must not win ties as free). No run with an accuracy → exit 2 (Rishi decides). `latest_summaries` skips smoke and stopped runs.
- Candidates (`ask.candidates`): a model may have two entries (low / none at the default reply cap, a high effort with its own `max_tokens: 16000`, `timeout_s: 120`); `--candidates` passes each entry's cap and timeout, the command line wins. `make_llm(model=...)` applies a candidate's first effort and routing only to a model that **isn't** `ask.llm.model`: the configured model always runs as `ask.llm` says (the winner is listed at the efforts it was tried at).
- W&B config keys must not contain `token`, `secret`, `password`, `api_key`, `credential` (`tracking.assert_no_secrets` raises at `wandb.init`): the reply cap is logged as `max_output`. The eval tests use `use_wandb=False`, so `test_the_run_config_passes_the_wandb_secret_check` runs the saved config through the check.

## 8. Tests (`tests/ask/test_ask_*.py`)

- Unit tests over tmp_path parquet fixtures and fakes (a fake driver, a scripted LLM, `httpx.MockTransport`); the red-team files for each guard; `-m integration` (`test_ask_guard_live.py`): the README §2 probes on the real Neo4j and curated folder, and the graph's counts unchanged. ## 9. Quirks found in AE00 (checked live 2026-10-17)

- Neo4j: a timeout stops a heavy read ~1 s past the limit (11.3 s for 10 s); a cold HDD page cache can make a first DEPTH_CHART or APPEARED_IN read take 4-8 s (warm: under 0.3 s): AE01 may want a warm-up query.
- DuckDB 1.5.6: `duckdb_settings()` lists local paths (the cwd in `allowed_paths`); `query('...')` accepts only a SELECT; `extract_statements` maps `PRAGMA`, `DESCRIBE`, `SHOW`, `SUMMARIZE` to SELECT (they fail `json_serialize_sql`, so they're refused as `sql.parse`); a registered table can be dropped by a later statement in the same connection (one connection per question, and SELECT only).
- Data traps (the audit, 2026-10-18): `officials` changed ids in 2023 (108 officials have two `official_id`s: group by name); `games.home_coach` / `away_coach` are nflverse's, wrong for three 2026 hires, a misspelling and the 2025 interims: the SQL sandbox applies `config/head_coach_fixes.csv` in `SqlSandbox._games_with_fixes` (as the graph build does); Super Bowl LIII (`2018_21_NE_LA`) has `APPEARED_IN.team_id` swapped for some players; the graph's official is "Ronald Torbert", `games.referee` says "Ron Torbert"; a second "Lamar Jackson" (a CB, `00-0036152`) exists, so name-matched Cypher references filter on position; "London" alone resolves as an ambiguous surname (Drake London and another), so a question naming the city asks "which one?" before the router could refuse.
- Haiku 5.5 at "xhigh" once returned JSON with extra text after it on 5 router calls in a row ("Extra data": an error, scored wrong); 4 probe calls on the same questions came back clean. Raw replies aren't kept; `parse_object` still refuses a reply with several objects (taking the first could pick the wrong one).
- OpenRouter (2026-10-17): `z-ai/glm-5.3-flash` rejects `reasoning.effort: none` (HTTP 400); `inception/mercury-2.5` still reasons a little at "none"; prices moved since 2026-10-08 (GLM 5.3 Flash $0.048 / $0.20, DeepSeek V4.1 Flash $0.072 / $0.144 per million).
