# Knowledge graph: build, query, test

The spec is `documentation/05-knowledge-graph.md` (schema, query sketches) plus its "As built in P05 / P08" sections; decisions D58–D62 (+ the P08 entries). Reader guides: `documentation/guides/knowledge-graph.md` and `documentation/guides/graph-data-science.md` (GDS + a Browser walkthrough). Code lives in `src/nflengine/graph/`; the digest side is `src/nflengine/digest/graph_sections.py`. Neo4j runs in Docker (`nfl-neo4j`, 5.26 Community + APOC + GDS), data bind-mounted on D:. Wiping and rebuilding the graph, and starting / stopping the container, need no approval (CLAUDE.md).

## 1. The pipeline (`nfl graph build --season S --week W [--backtest]`)
`graph/build.py::run_graph_build` → `build_graph`:
1. **Inputs + tables** (`graph/tables.py`, pure Polars, ~2 s): `load_inputs(paths, key)` reads curated Parquet + feature tables + the week's `predictions_games.parquet` + the published-insight log; `build_tables(inputs, key)` returns one frame per node label and relationship type. Relationship frames have `s` / `e` (endpoint keys) + properties; rows whose endpoints aren't nodes are dropped and counted (`GraphTables.dropped`; `DRAFTED_BY` drops thousands of pre-2018 players, which is expected).
2. **Wipe** (`CALL (r) { DELETE r } IN TRANSACTIONS`, then nodes), **schema** (`schema.cypher`, idempotent, ~12 s for index awaits), **load** (`UNWIND $rows`, nodes `CREATE ... SET n = r`, relationships `MATCH` both keys + `CREATE ... SET x = r.p`; 5k / 10k per transaction).
3. **Count check**: `graph_counts` must equal `GraphTables.expected_counts()`; a mismatch raises `GraphCountMismatch` before any query runs, so the build is `unavailable` (fail-soft: the weekly step is `degraded`, the digest shows the banner; `nfl graph build` exits 2).
3b. **GDS jobs (P08, `graph/gds.py::run_gds_jobs`, §6c)**: `pass_network` writes `PASS_CENTRALITY`, `player_similarity` writes `SIMILAR_TO`; never raises; recorded in `graph_results.json["gds"]` and W&B `gds/*`. Written after the count check, so not in it.
4. **Query library** (`graph/queries/`), **candidates + selection** (`graph/insights.py`), **`graph_results.json`** in the run folder (live `runs/<S>/week<NN>/`, backtest `runs/digest-backtests/<S>/week<NN>/`). W&B: group `track1-graph`, job `build`, live `load/*` curve per table, `count/*`, `time/*`, `query/*`, tables of candidates and picks, and the artifact `graph-results` (type `graph`, `graph_results.json`, alias `<season>-w<NN>` / `-backtest`). The reader-facing explanation is `documentation/guides/knowledge-graph.md`; keep it current with this skill.

Measured (2026 week 4, HDD bind mount): ~15.5k nodes, ~590k relationships, ~90 s total (APPEARED_IN ~23 s, DEPTH_CHART ~22 s). Every library query < 1 s. P08 adds ~1.8k `UsageProfile` nodes (+ `HAS_PROFILE`) and ~12 s of GDS (2025 backtests: ~140 s -> ~153 s on the HDD; wipe and load times swing ±20 s run to run).

## 2. As-of visibility (the leakage rules)
`GraphKey(season, week, run_time, mode)`: live = now; backtest = 14:00 UTC on the Tuesday before the week's first kickoff (`digest.run.tuesday_before`). The table in `graph/tables.py`'s docstring is the contract. In short: results only from completed games strictly before week W; week-W games are nodes without scores; rosters before W; week-W depth charts only if dated by the run date; week-W injury reports only if modified by the run time, and **undated 2025+ reports only in live runs** (D62); trades by the run date; `TeamWeek` up to W. When you add a relationship, add its rule to that table and a test (see `tests/graph/test_graph_tables.py`).

P08 rules (same docstring): **officials** of week W only in a live run that has them (a backtest never: crews are published after the game, weeks late); **FTN** (`PLAYED_IN.pa_rate`) strictly before W, and a backtest also drops week W-1 (`tables_extra.visible_ftn`; `date_pulled` is a refresh time, rewritten on every pull, so it can't date a row); **QB style / usage profiles** from visible plays (`usage_profiles` re-filters `key.before()` itself); **coaching seed** rows with season <= S; **GDS outputs** are computed from the loaded as-of graph, so they inherit everything.

## 3. Schema notes (beyond doc 05)
- Keys: `Team.team_id`, `Player.player_id` (GSIS), `Game.game_id`, `Coach.coach_id` (name slug), `Venue.stadium_id` (resolved with `features.venues.game_travel`, so 2025 international games are at the right stadium), `Official.official_id`; model outputs have one string `key` each (`TeamWeek` "KC:2026:4", `GamePrediction` "game\|version\|variant", `PublishedInsight` "2026-w4:<insight_id>"). `PlayerProjection.key` is constrained (P06 fills it: §6b).
- `Game.home_qb_expected` / `away_qb_expected` (week-W games): the game model's expected starters, with `home_qb_source` / `away_qb_source`. Only `schedule`, `depth_chart`, `injury_next` (a live run) confirm a starter; a Tuesday-rule pick (`last_game` ...) is "could start, not confirmed" in Q3's text (every backtest QB change is unconfirmed, as it would have been on that Tuesday).
- `PLAYED_FOR {season, first_week, last_week, weeks, roster_weeks, status_last, games}`: `roster_weeks` is the actual list (a stint away leaves a gap); `status_last = 'RES'` = on a reserve list at the latest roster week.
- `APPEARED_IN`: box score full-joined with snaps (`off_snaps`, `def_snaps`, `st_snaps`, `snaps` = off + def and **null when there's no snap record**, `snap_pct` = max of the two pcts), `pressures` lagged a week in backtests (PFR is late), `epa`, `pressures` (PFR), `qb_started` (most dropbacks for his team), `dropbacks`, NGS `ngs_separation` / `ngs_time_to_throw` / `ngs_ryoe`.
- `PLAYED_IN {home, points, points_allowed, margin, result, epa_per_play, epa_allowed, epa_margin, success_rate, plays, penalties, st_epa, st_plays}`; week-W rows exist (so queries find this week's opponent) with null results. `st_epa` = net special-teams EPA for the team (kickoff / punt / field goal / extra point by `play_type`, each play centered on the league mean for its season and play type; the two sides of a game sum to 0).
- `TeamWeek.prior_weight`: share of last season's prior still in the rating (1.0 in week 1, ~0.5 in week 4, ~0.45 in week 5).
- `DEPTH_CHART` is per (player, team, season, week, position), offense and defense slots only. **Slot formats differ**: ≤2024 has three rank-1 `WR` rows (one per slot), 2025+ one ranked `WR` list (1..8). Don't infer "the backup" from rank + 1 at WR / CB; Q2 uses usage data instead.
- **P08 additions** (`graph/tables_extra.py`): `APPEARED_IN.scrambles` / `air_yards` / `air_att` (QB style per game; aggregate in Cypher over any window); `PLAYED_IN.pa_rate` / `pa_dropbacks` (FTN, >= 10 charted dropbacks); `UsageProfile {key "<pid>:<season>", group, current, games, shares..., yds_rank, basis, vector}` + `HAS_PROFILE` (WR / TE / RB seasons, regular season; floors: past >= 8 games and 40 opportunities, current >= 3 and 12; `vector` = z-scores within the group over every profile in the window); coaching seed (`config/coaching_seed.csv`, D86) `COORDINATOR_OF {season, role}` (OC / DC / ST rows) and `WORKED_UNDER {seasons, teams, roles}` (every seed row -> that team-season's head coach, from HEAD_COACH_OF or the row's `head_coach`), seed coaches added as `Coach` nodes. GDS writes `PASS_CENTRALITY {season, week, team_id, role, pagerank, degree, share, rank, hub_id, out_this_week, share_this_week, rank_this_week}` (Player -> Team) and `SIMILAR_TO {season, other_season, other_team, group, score, rank, basis, week}` (Player -> Player).

## 4. Query library (`graph/queries/*.cypher`)
Each file takes `$season`, `$week` (+ the extras in `LIBRARY`) and returns rows with the entities, numbers already computed, `insight_type`, `strength` in [0, 1] and `sample_size`. Insight queries: Q1 revenge, Q2 injury ripple, Q3 QB change, Q4 common opponents, Q5 coach reunion, Q8 trend mismatch, Q11 unit mismatch, Q12 special teams (converters for Q5 / Q11 / Q12 live in `insights_extra.py`). `q0_starters_out` is a **data** query (`insights.DATA_QUERIES`): no converter, its rows feed the digest's code-written Starters out list. Run one by hand: `uv run nfl graph query q2_injury_ripple --season 2026 --week 4` (read transaction). Definitions are D59. Neo4j 5.26 syntax used: `CALL (x) { ... }` scoped subqueries, `OPTIONAL CALL`, `EXISTS { MATCH ... }`; old `CALL { WITH x ... }` prints deprecation notices.

P08 queries (converters in `insights_advanced.py`): `q5_coaching_tree` (`coaching_tree`; only with the seed; `UNION ALL` of coordinator-vs-former-boss and `shortestPath((h1)-[:WORKED_UNDER*1..2]-(h2))`), `q6_former_teammates` (QB from `Game.<side>_qb_expected`, any `THREW_TO` history >= 40 targets, receiver now on the opponent), `q7_style_matchup` (QB scrambling / deep passing) and `q7_play_action` (its own type `play_action`: the tests require one insight type per query), both comparing the defense's split against the style with the league's split (`gap`), `q9_officiating` (`officiating`, always low confidence, strength <= 0.5), `q10_network_hub` and `q10_usage_comp` (read the GDS outputs). New subject roles: `former teammate`, `usage comparison` (`facts.GRAPH_SUBJECT_ROLES` must stay equal to `insights.SUBJECT_ROLES`; a test checks). A referee is a `GraphPerson` with `player_id = "official:<id>"` and `team = ""` (naming him names no team).

**Adding a query:** a `.cypher` file + its `LIBRARY` entry (extra params) + a converter in `insights.py::CONVERTERS` (code-made headline + facts with owners, a stable `insight_id`, `sample`, `confidence`) + its section in `SECTION_TYPES` + the type in `digest/payload.py`'s `GraphInsight.insight_type` Literal + tests (converter wording; a golden week in `tests/graph/test_graph_integration.py`). Keep queries read-only. `run_query` opens its session with `QUIET` (UNRECOGNIZED notifications off): a query naming a type an optional input didn't create (no seed, a failed GDS job) otherwise logs a "does not exist" warning through the driver on every build; `graph_counts` does the same.

## 5. Insights → digest
- `insights.candidates` turns rows into `GraphInsight` payload items (each with a code-written one-line `brief`); `insights.select` scores (+0.1 followed team), skips started games, novelty (same `insight_id` in the 3 earlier weeks of the season) and a player already used, then picks 1 for `matchup_risk` (QB changes at `QB_RISK_WEIGHT` 0.8: they're all in the game table already) and 1–2 for `non_obvious` (low-confidence unit mismatches excluded), then up to `MORE_MAX` strong leftovers for the code-written "More from the graph" list (D60, D63).
- **A converter never sinks the build** (P08): `candidates(..., errors=)` skips a row its converter can't turn into an item (an unexpected null in a formatted field, a new edge case) and records the query with the exception's type name; `build.py` logs it and writes `converter_errors` into `graph_results.json`. Before this, one odd row in any query failed the whole build and the digest lost every graph section. A non-empty `converter_errors` is a bug to fix in the converter.
- **Meaning stays in code** (D53 lesson): facts are complete, time-scoped, self-describing phrases ("... the 49ers defense allowed +0.11 EPA per play ... : worse without him"). Never put a bare number, sign or comparison in a fact for the LLM to interpret. Numbers come from `digest/format.py` (`F.epa`, `F.per_game`, `F.share`, `F.epa_change`).
- Novelty's source of truth is `published_insights.parquet` (`graph/published.py`). It only grows: a re-run adds its picks and never erases one already published. The digest logs only the picks its final prose names (`graph_sections.rendered`), after publishing; live runs also MERGE them as `PublishedInsight` nodes (backtests don't touch the live graph). Every rebuild reloads the log's earlier weeks as nodes.
- A live digest skips games kicking off within 90 minutes (`LIVE_KICKOFF_MARGIN`): GLM can take 20+ minutes.
- **Say what the uncertainty is about.** A low-confidence item's `note` names the uncertain claim (Q3: the new QB's career targets to these receivers); the prompt puts the hedge there, never on the headline (the P05 fact-check found GLM hedging a well-supported QB start). Say *why* when the data has it (the main starter listed Out), and name a snap share's side (offense / defense).
- Ownership: one claim per fact clause; a receiver's targets fact is "X has 20 targets from A this season; he has 12 from B since 2018", owned by A and B (each owns only the clause naming him), not by the receiver.
- The digest (`digest/graph_sections.py`) re-picks from the stored candidates with its own run time; `--graph auto|build|read|off`.

## 6. Fail-soft
`run_graph_build(..., fail_soft=True)` (weekly step, digest, `nfl graph build`) never raises: it writes `{"status": "unavailable", "error": "<Type>: <short reason>"}`. Never write a driver's exception text anywhere (files, logs, W&B; it can carry server text): `graph.client.safe_error` keeps the type plus a fixed reason or the Neo4j status code (`Neo.ClientError...`), and `run_query` uses it too (a test injects a sentinel). The weekly `graph` step then raises `StepDegraded` (recorded as `degraded`, the run continues) and the digest shows the ℹ️ banner. Check by hand: `docker compose stop neo4j`, `uv run nfl weekly run --season S --week W --from-step graph --llm placeholder`, then `docker compose start neo4j` and wait for "Started." in `docker compose logs neo4j`.

**P07:** the weekly `graph` step first calls `ops.services.ensure_neo4j()` (ping; start Docker Desktop if the engine is down; `docker compose up -d` once; wait up to `ops.neo4j_start_timeout_s`) and only degrades if that fails. Checked live 2026-10-04: container stopped → up again in 50 s. Its output is never echoed (compose can print variable warnings).

**Restoring the live graph after a backtest build.** Any backtest graph build (`nfl digest --backtest`, `nfl graph build --backtest`, the integration tests; `--as-of` simulations skip the graph since the P07 review) wipes the live graph. To restore week W exactly as published without touching its records: copy `runs/<S>/week<WW>/graph_results.json` aside, `run_graph_build(S, W, mode="live", run_time=<that file's run_time>, use_wandb=False)`, check `counts` and `selected` match, copy the saved file back, then `write_projections(pl.read_parquet(<week>/predictions_players.parquet))`. Done after the P07 simulations: identical counts (15,522 / 588,330), identical picks, 1,860 projections.

## 6b. Player projections (P06, `graph/projections.py`)
- `write_projections(preds, client=None, log=print, batch_size=5000) -> ProjectionWriteResult` (`status` ok / unavailable / skipped, `nodes`, `linked_players`, `linked_games`, `seconds`, `error`, `.summary` one log line). Called by the weekly `player` step after `nfl train player` (D67); the `graph` step runs first and wipes the DB, so projections are always written after the build. Backtests never write them.
- Key `<player_id>|<game_id>|<target key>|<model_version>` (`projection_key`): the target key (`tackles-lbs`) keeps a linebacker's pressures and tackles projections apart. Duplicate rows in one call collapse to the last.
- Idempotent: `UNWIND` → `MERGE (pp {key})` → `SET pp = r.props` → `OPTIONAL MATCH` Player / Game → `FOREACH ... MERGE` the two edges. No `CREATE` (a test asserts it). Unlinked projections (no Player / Game node) are still written and counted.
- Properties: the `PROPS` list (PRED_SCHEMA's numbers and labels), `created_at` as ISO text, `top_drivers` = phrases. NaN and null are left out.
- Fail-soft through `safe_error` (a test injects a sentinel message and checks it never reaches the result or the log). Not in `graph_counts` / the build's count check.
- Indexes: `projection_season_week`, `projection_player` (`schema.cypher`).

## 6c. GDS jobs (P08, `graph/gds.py`)
- `run_gds_jobs(driver, key, log) -> GdsResult` (status ok / partial / unavailable, `version`, `seconds`, `jobs[name] = {status, seconds, written, ...}`, `.summary`). Checks `gds.version()`, drops leftover `nfl-*` projections, runs each job in its own try (a failed job is `failed` with `safe_error` text and its projections dropped), never raises.
- `pass_network`: ONE Cypher-aggregation projection of this season's `THREW_TO` (undirected, weight `targets`, `relationshipType: t.team_id`), per team `gds.degree.stream` + `gds.pageRank.stream` with `relationshipTypes: [team]` (filter the stream with `WHERE nodeId IN $ids`: every other team's node is in the projection too). Shares = PageRank among receivers (QBs out). Then the library's Q0 (`out_receivers`) gives this week's out WR / TE / RB; a second projection without their edges (`$exclude` "TEAM:pid") gives `share_this_week` / `rank_this_week`. Two projections, ~100 stream calls, ~11 s.
- `player_similarity`: per group a node-only projection of `UsageProfile` (`gds.graph.project($name, u, null, {sourceNodeLabels: CASE ... ['Current'] / ['Past'], targetNodeLabels: NULL, sourceNodeProperties: {vector: u.vector}, targetNodeProperties: NULL})`: with source labels you **must** pass `targetNodeLabels: NULL`), then `gds.knn.filtered.stream` (`nodeProperties: {vector: 'EUCLIDEAN'}`, `sourceNodeFilter: 'Current'`, `targetNodeFilter: 'Past'`, `topK 10`, `randomSeed 42`, `concurrency 1`); the player's own seasons dropped, top 3 written. ~1 s.
- **Memory:** heap 2 GB. Never give each (team, receiver) pair its own relationship type: ~1,000 types threw `Neo.TransientError.General.OutOfMemoryError` (Neo4j recovered by itself). A projection of zero rows creates nothing (check `nodeCount` before streaming).
- **PageRank on these networks ~ weighted degree** (star-shaped QB-receiver graphs): it's a principled "who the passing game went through", not hidden structure; the converter's note says so. Season-total centrality drifts when a star misses weeks (his total falls behind), which is why the hub story uses Q0's out list and ranks <= 3, not only rank 1.
- By hand: `uv run python -c "..."` with `run_gds_jobs(get_driver(), GraphKey(...))` reruns the jobs on the loaded graph (delete old `PASS_CENTRALITY|SIMILAR_TO` first; the writes `MERGE`, so a rerun only updates).

- Integration (`uv run pytest -m integration tests/graph/test_graph_integration.py`, ~15 min): golden weeks (Saquon Barkley vs the Giants, 2024 w7; Justin Jefferson on IR, 2023 w7 + the GDS hub (Hockenson leads without him) and Puka Nacua ~ Diggs 2020; Jake Browning for Burrow, 2023 w13; P08 2024 w14: Cousins vs Jefferson (Q6), Hurts scrambling (Q7), FTN week lag, GDS degree sums = 2 x targets, the coaching tree from a test seed (monkeypatched `tables_extra.seed_path`), Q9 with Alex Kemp's crew added by hand), GDS errors on the real server fail-soft, no week-N results / crews in a Tuesday graph, counts = tables and repeatable, every query < 2 s, fail-soft with an unreachable driver. ## 9. Quirks found in P05 (checked live 2026-10-03)
- `officials.game_id` is the old GSIS id (`2015091000`): join on `games.old_game_id` (16,154 of 16,182 rows since 2018 match).
- `injuries.date_modified` is null for every 2025+ row (D62).
- `trades` rows for traded **draft picks** carry the eventual draftee's `pfr_id` (`pick_season` set): exclude them from player trades (2,737 of 3,943 rows with a `pfr_id`).
- Depth-chart slot formats (see §3).
- Neo4j's `SET n = map` skips null values, so absent properties read as null in Cypher; `coalesce` where it matters.
- nflverse `special_teams_play` is 0 on every field goal: select special-teams plays by `play_type`. On a kickoff `posteam` is the receiving team. Since 2024 a kickoff averages about +0.25 EPA to the receiver and a field goal about +0.2 to the kicker, so raw special-teams EPA punishes teams that kick off a lot: center per (season, play type).
- Head coaches before 2018 aren't in the graph, so Q5 can't see older reunions (Reid at PHI) and scopes records "from 2018 on".

## 9b. Quirks found in P08 (checked live 2026-10-04)
- `officials` lags weeks: on 2026-10-04 it had 2026 week 1 only (weeks 2-4 played). Week-W crews are never there on a Tuesday, so Q9 is quiet in practice.
- FTN `date_pulled` is the time of the last refresh (all 2025 rows say 2026-09-23), not first availability: use the week lag rule, not the date.
- GDS Cypher projection with `sourceNodeLabels` needs `targetNodeLabels: NULL` (and the same for properties) when the target is `null`, else `ProcedureCallFailed`.
- **The coaching seed is built, not hand-made** (D86): `uv run nfl graph coaching-seed [--refresh]` (`graph/coaching_seed.py`) parses Wikipedia team-season articles' `{{NFL final staff}}` template (infobox fallback; the current season from `Template:<Team> staff`), cached under `cache/http/wikipedia_staff/`; coordinators only (OC / DC / ST; adding position coaches would link almost every pair of head coaches within 2 hops). Re-run with `--refresh` each preseason. Read its **name check** output: a Wikipedia name that slugs differently from nflverse's head-coach name splits one coach into two nodes; fix it in `NAME_FIXES`. Keep only real `"name"` values in `head_coach`: a blank must reach the frames as null (the reader maps `""` to null; before that fix a quoted blank beat the schedules' head coach and every 2018+ `WORKED_UNDER` edge was lost: 406 vs 771).
- A seed row for a coordinator's *current* team also makes him `WORKED_UNDER` his current head coach, so `shortestPath` between two head coaches can run through him instead of an old mentor (both are real links; the golden test accepts either).
- `UNION ALL` queries need identical column names in the same order in every part.
